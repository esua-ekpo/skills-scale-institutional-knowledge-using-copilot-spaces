# OctoAcme — Role Accountability Checklist

## Purpose
Provide a lightweight checklist to confirm that roles, responsibilities, and decision ownership are clear for each project.

## When to use
- At project kickoff
- During sprint planning or backlog refinement
- Before a major release or milestone
- When new team members or stakeholders join the project

## Checklist
- [ ] Project sponsor and executive stakeholders are identified
- [ ] Product owner / Product Manager is assigned
- [ ] Project Manager is assigned and communication cadence is agreed
- [ ] Technical Lead is identified for architecture and technical trade-offs
- [ ] QA / Test Lead is assigned for validation strategy and release readiness
- [ ] Security / Compliance Partner has reviewed high-risk requirements and controls
- [ ] Customer Success / Stakeholder Liaison is identified for external communication and adoption impact
- [ ] Escalation path for blockers is documented
- [ ] Risk owners are named for each significant risk
- [ ] Dependency owners and decision-makers are visible in the project board
- [ ] Role ownership is reviewed during sprint planning and milestone reviews

## Decision Ownership Notes
- If ownership is unclear, the default decision owner should be the relevant functional lead and not the whole team.
- Document cross-functional handoffs in the project board, roadmap, or planning notes.
- Review role clarity as projects scale, change direction, or add new dependencies.
